## Additional Notes

## Flashing

Flashing needs some extra arguments after `run`: `-- --allow-erase-all --no-catch-reset`, example:
```
laze build -b nordic-thingy-91-x-nrf9151 run -- --allow-erase-all --no-catch-reset
```

- `--allow-erase-all` can help `probe-rs` to recover the chip if it ends up in an unrecoverable state.
- `--no-catch-reset` tells `probe-rs` to ignore the reset that happens during the chip initialization. The reset is a mitigation of a hardware issue, see [embassy PR #4417](https://github.com/embassy-rs/embassy/pull/4417).

You may need to run the flash command 2–3 times before it succeeds.

If flashing still fails, you may try to use the `recover` and `erase` command of `nrfutil`:
```
nrfutil device recover && nrfutil device erase
```
and then power cycle your board.

## Updating the modem firmware

Some nRF9151 chips may ship with a modem firmware incompatible with Ariel OS, if you see an error like this one, you may need to update the modem's firmware:
```
[ERROR] panicked at 'Modem fault - reason: 16, pc: 257104' (nrf_modem nrf-modem-0.10.2/src/lib.rs:337)
```
- Install the [proprietary `nrfutil` tool](https://www.nordicsemi.com/Products/Development-tools/nRF-Util)
- Install the `device` module:
  ```
  nrfutil install device
  ````

- Go to the [nRF9151 Downloads page](https://www.nordicsemi.com/Products/nRF9151/Download?lang=en#infotabs) and download the latest package in "nRF91x1 SiP LTE firmware".
- Connect your debug probe to the board and ensure that it's powered up and connected to the nRF9151 (on Thingy:91 X the debug probe is connected to  the P8 header; SW1 must be on the ON position and SW2 on the nRF91 position).
- Flash the firmware, replace `<modem.zip>` by the name of the archive you downloaded (for example `mfw_nrf91x1_2.0.4.zip`):
  ```
  nrfutil device recover && nrfutil device program --firmware <modem.zip>
  ```
- Then power-cycle the board once.
